## 🎯 Objectif

Ce document décrit l'implémentation technique du système d'identification automatique des copies par OCR (Optical Character Recognition), utilisant l'IA générative pour la lecture de l'écriture manuscrite.

---

## 🤖 Architecture OCR (Dual-Engine)

Korrigo utilise deux moteurs complémentaires pour garantir une identification fiable :

### 1. GPT-4o-mini Vision (Moteur Principal)
- **Technologie** : Large Language Model avec capacités de vision (OpenAI).
- **Usage** : Lecture de l'écriture manuscrite cursive sur les en-têtes.
- **Avantages** : Compréhension contextuelle du français, excellente tolérance aux ratures et à l'écriture peu lisible.
- **Workflow** : L'image de l'en-tête (crop 25%) est envoyée en Base64 à l'API OpenAI avec un prompt spécifique.

### 2. Tesseract OCR (Moteur de Fallback)
- **Technologie** : OCR classique basé sur LSTM (Google).
- **Usage** : Secours en cas d'absence de connexion internet, de clé API manquante ou de dépassement de quota.
- **Avantages** : Exécution locale, gratuité, rapidité.
- **Configuration** : `lang=fra+eng`, `--psm 6` (bloc de texte uniforme).

---

## 🔍 Pipeline de Traitement

### 1. Extraction (Detection)
Le système ne traite pas la page entière pour l'identification. Il effectue un **crop dynamique** des 25% supérieurs de la première page du livret (`Booklet`).
- **Fichier** : `backend/identification/services.py` -> `extract_header_from_booklet()`

### 2. Reconnaissance (OCR)
- L'image cropée est passée au service `OCRService.perform_ocr_on_header()`.
- Si `OPENAI_API_KEY` est configurée, GPT-4o-mini est sollicité.
- Sinon, Tesseract prend le relais localement.

### 3. Matching Étudiant (Fuzzy Search)
Une fois le texte extrait (ex: "JEAN DUPONT"), le système effectue une recherche floue dans la base de données des étudiants.
- **Algorithme** : Recherche par mots-clés (`icontains`) sur le nom et le prénom.
- **Résultat** : Une liste de candidats potentiels (Top-10) avec un score de confiance.

---

## 🛠 Configuration Technique

### Variables d'Environnement (Backend)
- `OPENAI_API_KEY` : Clé secrète pour accéder à l'API Vision.
- `OPENAI_MODEL` : Modèle à utiliser (défaut: `gpt-4.1-mini-2025-04-14`).
- `TESSDATA_PREFIX` : Chemin vers les données de langue Tesseract (dans le conteneur Docker).

### Sécurité & Coûts
- **Cache** : Les résultats OCR sont persistés dans le modèle `OCRResult` pour éviter de rappeler l'API inutilement pour une même copie.
- **Anonymisation** : L'OCR n'est utilisé que par les administrateurs/secrétariat lors de la phase d'identification. Les correcteurs ne voient jamais le résultat de l'OCR.
