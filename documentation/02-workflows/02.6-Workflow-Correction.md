# 02.6 - Workflow de Correction des Copies

**Projet** : Korrigo - Système de Correction d'Examens
**Version** : 2.1 (Production)
**Date** : 20 Février 2026
**Auteur** : **Alaeddine BEN RHOUMA**

---

## 🎯 Objectif

Le workflow de correction permet aux **enseignants** de corriger numériquement les copies d'examens en attribuant des notes par question, en ajoutant des annotations vectorielles et en générant des bilans pédagogiques par IA.

### Acteurs

- **Enseignant correcteur** : Corrige les copies qui lui sont assignées.
- **Administrateur** : Supervise le processus, gère le barème et les exports.

---

## 📊 Vue d'Ensemble du Workflow (Machine d'États)

```
READY ──lock──→ LOCKED ──finalize──→ GRADING_IN_PROGRESS ──→ GRADED
  ↑              │                           │
  └──unlock──────┘                    GRADING_FAILED (Retry)
```

### Étapes du Processus

1.  **Acquisition (Lock)** : L'enseignant choisit une copie `READY` et acquiert un verrou (`LOCKED`).
2.  **Annotation & Notation** : 
    - Ajout d'annotations vectorielles (Commentaires, Surlignages, Erreurs).
    - Saisie des points par question selon le barème.
    - Sauvegarde automatique du brouillon (`DraftState`).
3.  **Finalisation** : L'enseignant valide la correction.
4.  **Traitement (Asynchrone)** : Le système génère le PDF final avec annotations aplaties.
5.  **Bilan IA (Optionnel)** : Génération du bilan pédagogique personnalisé via Ollama.

---

## 📋 Étape 1 : Acquisition et Verrouillage

### Objectif

Garantir qu'un seul correcteur travaille sur une copie à la fois via un **verrouillage pessimiste**.

### Mécanisme (CopyLock)

- **Endpoint** : `POST /api/grading/copies/{id}/lock/`
- **TTL** : 10 minutes par défaut.
- **Heartbeat** : Le frontend envoie un signal toutes les minutes pour maintenir le verrou tant que l'onglet est ouvert.

---

## 🖊️ Étape 2 : Annotation et Notation

### Interface de Correction (Corrector Desk)

L'interface est divisée en deux zones :
- **Zone PDF (Gauche)** : Visualisation via PDF.js avec outils de dessin vectoriel.
- **Barème (Droite)** : Formulaire dynamique basé sur la structure de l'examen.

### Annotations Vectorielles

Les annotations sont stockées en coordonnées normalisées [0, 1] pour garantir la cohérence quel que soit l'écran ou la résolution du PDF.

**Types supportés** :
- `COMMENT` : Commentaire textuel.
- `HIGHLIGHT` : Surlignage de zone.
- `ERROR` : Signalement d'une erreur (- points possible).
- `BONUS` : Point bonus.

---

## 💾 Étape 3 : Sauvegarde Automatique (Autosave)

Le système utilise le modèle `DraftState` pour sauvegarder l'état de la correction toutes les 2 secondes après une modification. Cela protège l'enseignant contre :
- Les micro-coupures réseau.
- Les fermetures accidentelles de navigateur.
- Les expirations de session.

---

## 🔒 Étape 4 : Finalisation

### Processus

Lors de la finalisation (`POST /api/grading/copies/{id}/finalize/`) :
1.  **Validation** : Le système vérifie que toutes les questions obligatoires sont notées.
2.  **Transition** : La copie passe en `GRADING_IN_PROGRESS`.
3.  **Aplatissement (Flattening)** : Un worker Celery utilise PyMuPDF pour dessiner les annotations sur le PDF original et générer le `final_pdf`.
4.  **Succès** : La copie passe en `GRADED`.

---

## 🤖 Étape 5 : Génération du Bilan IA (Korrigo AI)

Une fois la copie `GRADED`, l'enseignant ou l'admin peut déclencher la génération d'un **bilan pédagogique**.

- **Technologie** : Ollama (LLM local type qwen2.5:32b).
- **Données sources** : Notes détaillées + Annotations + Appréciation globale.
- **Résultat** : Un texte structuré (Points forts, Axes d'amélioration, Conseils) qui tutoie l'élève.

---

## 📝 Conclusion

Le workflow de correction Korrigo allie la précision des outils numériques à la puissance de l'IA pour offrir un retour pédagogique riche et rapide aux élèves.
